1. 概觀與配置

FluxSECS 是一套專為 .NET 環境設計的高效能 HSMS / SECS-II / GEM 通訊元件。它聚焦於 SEMI E37 (HSMS)、E5 (SECS-II) 與 E30 (GEM) 的實務整合。

1.1 產品簡介與架構

核心架構

+-----------------------------------------------------------------------+ | User Application | +-----------------------------------------------------------------------+ | FluxSECS API | | (InitializeConfig, SendPrimary, OnDataMessage, SnFx) | +-----------------------------------+-----------------------------------+ | GEM Logic Layer | Message Handling | | (VID / EC / Alarm / Report / CE) | (SecsMessage / SecsItem) | +-----------------------------------+-----------------------------------+ | HSMS Transport Driver | SECS-II Message Engine | | (TCP/IP, T3-T8 Timers) | (Serial, T1-T4 Timers) | +-----------------------------------+-----------------------------------+

1.2 快速開始

快速上手流程

這裡用「最快可跑」為目標：讓你能在幾分鐘內完成連線、看到 Monitor/Trace、並跑通一組 S1F13 ↔ S1F14（再加上 S1F17 ↔ S1F18）。 若你需要更深入的訊息建構、GEM 資料/控制狀態、SnFx 詳解，請往後續章節延伸。

步驟 1：把必要檔案放到執行目錄

  • FluxSECS.dll
  • Connection.xml（通訊協定 / 角色 / 連線參數）
  • Standard.xml（Message定義；開發商自行定義）
  • GemConfig.xml（VID/EC/Report/CEID/Alarm 與 GemSetting）
  • License.license授權檔

InitializeConfig(...) 的四個 Path 參數若傳 null，會自動讀取以上預設檔名（位於執行目錄）。

步驟 2：建立 Connection.xml

目前網站與文件僅聚焦 HSMS 通訊。以下配置以實際已驗證的 HSMS / SECS-II 使用方式為主， 我把範例拆成兩份：你用哪一種，就保留那一份，另一份可以直接刪除。

2-1. HSMS 範例

								<ConnectInfo>
  <DeviceRole>Host</DeviceRole>     <!-- Host 或 Equipment -->

步驟 4：Console 快速驗證

Host 端的重點是：等 ConnectState 進入 Selected 後送訊，並在 OnDataMessage 中處理回來的 Secondary（例如 S1F14 / S1F18）。 

using System;
using System.Threading;
using FluxSECS;

class Program
{
    static void Main()
    {
        var secs = new SECS();

        // 1) 一次性初始化：若參數為 null，會讀取「執行目錄」下的預設檔
        //    Connection.xml / GemConfig.xml / Standard.xml / License.license
        secs.InitializeConfig(
            ConnectionPath: null,
            GemDataPath: null,
            StandardDataPath: null,
            LicensePath: null,
            debugmode: true,
            monitor: (m) => Console.WriteLine($"[MON] {m}"),
            trace:   (t) => Console.WriteLine($"[TRC] {t}")
        );

        if (!secs.LicenseValid)
        {
            Console.WriteLine("授權無效，無法啟動通訊。");
            return;
        }

        // 2) 監聽連線狀態：HSMS 建議等待 Selected 後再送 Data Message
        var selected = new ManualResetEventSlim(false);
        secs.ConnectStateChanged += (s) =>
        {
            Console.WriteLine($"[STATE] {s}");
            if (s == ConnectState.Selected) selected.Set();
        };

        // 3) 收到訊息（Primary/Secondary）
        secs.OnDataMessage += (type, msg) =>
        {
            Console.WriteLine($"[RX] {type} S{msg.Stream}F{msg.Function} W={msg.Reply} TID={msg.TID}");
            // Host 端通常處理 SecondaryIn（例如 S1F14 / S1F18）
        };

        // 4) 啟動連線
        secs.Start();

        // 5) 等待 Selected（HSMS 建議在 Selected 後再開始正式收送訊息）
        if (!selected.Wait(TimeSpan.FromSeconds(30)))
        {
            Console.WriteLine("等待 Selected 超時：請檢查 HSMSMode/Port/防火牆/對端是否已啟動。");
            secs.Close();
            return;
        }

        // 6) 最小驗證：送 S1F13 (Establish Comm) -> 等 S1F14
        secs.Standard_S1F13(modelName: "MY_MODEL", softRev: "1.0");

        // 7) 常見下一步：送 S1F17 (Online Request) -> 等 S1F18
        secs.Standard_S1F17();

        Console.WriteLine("Press ENTER to exit...");
        Console.ReadLine();
        secs.Close();
        secs.Dispose();
    }
}

步驟 5：Console 快速驗證

Equipment 端的重點是：在 OnDataMessage 收到 PrimaryIn 後，依需求回 SendSecondary。 下例示範用內建 Standard_S1F14 / Standard_S1F18 回覆。 

using System;
using FluxSECS;

class Program
{
    static void Main()
    {
        var secs = new SECS();

        secs.InitializeConfig(
            ConnectionPath: null,
            GemDataPath: null,
            StandardDataPath: null,
            LicensePath: null,
            debugmode: true,
            monitor: (m) => Console.WriteLine($"[MON] {m}"),
            trace:   (t) => Console.WriteLine($"[TRC] {t}")
        );

        if (!secs.LicenseValid)
        {
            Console.WriteLine("授權無效，無法啟動通訊。");
            return;
        }

        secs.ConnectStateChanged += (s) => Console.WriteLine($"[STATE] {s}");

        // Equipment 端：收到 Primary 就回 Secondary（示範 S1F13 / S1F17）
        secs.OnDataMessage += (type, msg) =>
        {
            if (type != TransactionType.PrimaryIn) return;

            Console.WriteLine($"[RX] PrimaryIn S{msg.Stream}F{msg.Function} W={msg.Reply} TID={msg.TID}");

            if (msg.Stream == 1 && msg.Function == 13)
            {
                // 回覆 S1F14
                secs.Standard_S1F14(msg, commAck: 0, mdln: "MY_EQP", softrev: "1.0.0");
            }
            else if (msg.Stream == 1 && msg.Function == 17)
            {
                // 回覆 S1F18
                secs.Standard_S1F18(msg, onlAck: 0);
            }
        };

        secs.Start();

        Console.WriteLine("Equipment ready. Press ENTER to exit...");
        Console.ReadLine();
        secs.Close();
        secs.Dispose();
    }
}

常見問題與排除

  • 一直停在 Connected / NotSelected：請檢查 HSMSMode（Active/Passive）、Port 是否被防火牆擋住、對端是否已啟動監聽或連線。
  • 要送訊但沒有成功：HSMS 建議在 ConnectState == Selected 後才送 Data Message；若已斷線（Disconnected）送訊會被忽略並寫入 Trace。
  • UI 程式卡住/跨執行緒例外：OnDataMessage 可能在背景執行緒觸發；WinForms/WPF 請用 Invoke/Dispatcher 回到 UI thread。
  • 看不到 Trace：Trace 受 DebugMode 控制；請在 InitializeConfig(debugmode: true) 或設定 secs.DebugMode = true。
  • 要快速定位封包問題：先看 Monitor（封包層 TX/RX），再開 Trace 看聚合後的內容與計時器/狀態細節。

✅ 下一步建議：若你要自訂訊息內容，請到「2.3 訊息建構基礎」與「2.4 基礎訊息收發」；若要直接用標準 API，請到「3. GEM 標準指令庫 (SnFx)」。

1.3 Connection.xml 參數說明

本節說明 Connection.xml 各欄位的用途與常見設定。 若你只想先完成「快速可跑」驗證，請直接使用 ➜ 1.2 快速開始 的「步驟 2」範例（HSMS）。

欄位 範例 說明
DeviceRole Host 角色：Host 或 Equipment。影響你在整合時「誰先送訊 / 誰回覆」的預期流程。
Protocol HSMS 通訊協定。現階段文件與網站僅列出實際驗證中的 HSMS 配置，元件會讀取對應的 <HSMS> 區段。
HSMSMode Active Active 主動連線（對外連出）；Passive 被動監聽（等待對方連入）。
LocalIP / LocalPort 127.0.0.1 / 5000 本機 IP/Port。Passive 模式主要依賴 LocalPort 作為監聽埠。
RemoteIP / RemotePort 127.0.0.1 / 5000 遠端 IP/Port。Active 模式會連往此位址。
DeviceID 0 SECS Device ID。雙方需一致（不一致時常見會引發 S9 類錯誤）。
LinkTestInterval 60 LinkTest 週期（秒）。設 0 表示不主動送（仍可回覆對方的 LinkTest）。
T3Time 45 資料訊息交易逾時（等待 Secondary）。常見 45 秒。
T5Time 10 重新連線等待/回復用計時（常見 10 秒）。
T6Time 5 控制訊息回覆等待（如 LinkTest）。常見 5 秒。
T7Time 10 Passive 等待 Select 的逾時計時（常見 10 秒）。
T8Time 5 網路封包層級等待（常見 5 秒）。

小提醒：若你在 HSMS 下要送資料訊息，建議等 ConnectState == Selected 後再送，最容易一次成功。

1.4 標準定義

Standard.xml 用於定義每個 SECS-II 訊息（SxFy）的結構規格，提供執行期的格式驗證（特別是 AutoS9F7 啟用時的 Illegal Data 判斷），以及離線/工具（例如依定義產生範例 raw）所需的樣板。

重點
  • 同一個 SxFy 允許多組定義（Name 不同即可）。驗證時會逐一比對，任一組完全符合即視為合法並停止往下比對。
  • List 子項目數量只由 Variables 決定：true 不檢查數量（較多/較少/一致皆合法）；false 必須與定義完全一致（較多或較少都不合法）。
  • Scalar（非 List）長度在 CheckLength="True" 時，使用 Min/Max 進行元素個數上下界檢查（Min=下限、Max=上限）。
  • Value/Values 僅作為讀入/範例值使用，不做固定值比對（不會因為值不同觸發 S9F7）。

1.4.1 驗證流程

  1. 收到 Primary Message 後，以其 Stream/Function（SxFy） 在 Standard.xml 尋找所有同 SxFy 的 <SecsMessage ...> 定義（即使 Name 不同也都納入）。
  2. 對每一組定義進行「結構比對」：由最外層 SecsItem 開始遞迴驗證（格式、List 規則、Scalar 長度規則）。
  3. 若任一組定義「完全符合」則視為合法；若全部不符合且 AutoS9F7 啟用，則回覆 S9F7 (Illegal Data)。

1.4.2 欄位與數值意義

欄位 說明
SecsMessage/Name 同一個 SxFy 的「定義名稱」。用於區分多組定義（例如：S1F1 A、S1F1 B）。驗證時會逐一定義比對，任一組完全符合即通過。
SecsMessage/Stream, Function 對應 SxFy（例如 Stream=1, Function=1 代表 S1F1）。作為定位候選定義的主要鍵值。
SecsMessage/Reply 描述此 Primary 是否預期有 Secondary（屬於訊息特性描述；不作為 S9F7 的固定值判斷）。
SecsItem/SecsFormat 指定此節點的 SECS-II 型別（例如 List, ASCII, U1, I4 等）。
SecsItem/SecsFormat_Def 允許多個型別（以空白分隔），例如 "U4 ASCII" 代表此節點可接受 U4 或 ASCII。屬於「格式集合」驗證。
SecsItem/Variables 只對 List 有意義。
  • Variables="True"：可變動結構，不檢查 List 子項目數量（較多/較少/一致皆合法）。
  • Variables="False"：固定結構，List 子項目數量必須完全一致。
補充：所謂「定義的子項目數量」不是 XML 的獨立屬性，而是該 List 節點底下 <SecsItem .../> 子節點的數量。
SecsItem/CheckLength 元素個數比對開關（預設為 True）。
本專案規則：僅針對 Scalar（非 List）生效，並以 Min/Max 作為元素個數上下界。List 的數量規則不由 CheckLength 控制，請改用 Variables。
SecsItem/Min, Max 僅在 Scalar 且 CheckLength="True" 時使用。
  • Min：元素個數下限（Lower bound）。
  • Max：元素個數上限（Upper bound）。
  • 數值 0 代表「不設定該邊界」（例如 Min=0 表示不檢查下限；Max=0 表示不檢查上限）。
  • 若 Min > Max（上下界顛倒），視為「不做長度卡控」（不會因長度觸發 S9F7）。
例：ASCII Min="0" Max="3" 表示 ASCII 字串長度可為 0~3；U1 Min="1" Max="2" 表示 U1 元素個數必須在 1~2 之間。
SecsItem/Value, Values 範例值/預設值。用於讀入或產生範例訊息（例如依 Standard.xml 產生 raw 作為測試）。
不做固定值比對：實際收到的值與此處不同，不會因此觸發 S9F7。
SecsItem/Remark 備註/說明文字，常用於註記欄位語意（例如參數名稱）。不影響驗證結果。

1.4.3 範例

以下展示常見用法：Scalar 長度限制、List 的 Variables 規則、以及同一個 SxFy 多組定義。

（1）Scalar：用 Min/Max 描述元素個數上下界

								<SecsItem SecsFormat="ASCII" CheckLength="True" Min="1" Max="64" Remark="MODEL_NAME" />
<SecsItem SecsFormat="U1"    CheckLength="True" Min="0" Max="2"  Remark="FLAGS" />

（2）List：用 Variables 決定是否檢查子項目數量

								<!-- 固定結構：必須與定義完全一致 -->
<SecsItem SecsFormat="List" Variables="False">
  <SecsItem SecsFormat="U1" />
  <SecsItem SecsFormat="U1" />
</SecsItem>

<!-- 可變動結構：不檢查子項目數量（較多/較少/一致皆合法） -->
<SecsItem SecsFormat="List" Variables="True">
  <SecsItem SecsFormat="ASCII" Remark="CPNAME" />
  <SecsItem SecsFormat="ASCII" Remark="CPVAL" />
</SecsItem>

（3）同一個 SxFy 多組定義：逐一比對，任一完全符合即通過

								<SecsFormat>
  <!-- S1F1 定義 A -->
  <SecsMessage Name="S1F1_A" Stream="1" Function="1" Reply="True">
    <SecsItem SecsFormat="List" Variables="False">
      <SecsItem SecsFormat="ASCII" CheckLength="True" Min="0" Max="16" Remark="A_FIELD" />
    </SecsItem>
  </SecsMessage>

  <!-- S1F1 定義 B -->
  <SecsMessage Name="S1F1_B" Stream="1" Function="1" Reply="True">
    <SecsItem SecsFormat="List" Variables="False">
      <SecsItem SecsFormat="U1" CheckLength="True" Min="1" Max="2" Remark="B_FIELD" />
    </SecsItem>
  </SecsMessage>
</SecsFormat>

1.5 GemConfig.xml 參數說明

GemConfig.xml 用來定義 GEM 的資料模型（VID/EC/Report/CEID/Alarm）與自動化開關（GemSetting）。 若你只想先完成「最快可跑」驗證，請直接使用 ➜ 1.2 快速開始 的「步驟 3：最小 GemConfig.xml」。

GemSetting（自動化開關 / 行為設定）

欄位 範例 說明
DefaultOnlineState 0 預設 Online 狀態（依你的整合策略設定；不確定就先用 0）。
TimeFormat 2 時間格式設定（不確定就先用 2）。
AutoS9F1 True 收到不合法 Device ID 時，是否自動回 S9F1。
AutoS9F3 True 收到不合法 Stream Type 時，是否自動回 S9F3。
AutoS9F5 True 收到不合法 Function Type 時，是否自動回 S9F5。
AutoS9F7 True 收到資料格式不符 Standard.xml 定義時，是否自動回 S9F7。
AutoS9F9 True 交易逾時（發送 Primary 後 T3 內未收到 Reply）時，是否自動回 S9F9。
AutoS9F11 True 收到資料過大或訊息長度超出限制時，是否自動回 S9F11。

VIDs（變數定義）

<VIDs> 內包含多筆 <VID ... />。每一筆代表一個可讀/可回報的變數（SVID / DVID）。

屬性 範例 說明
ID 1001 VID 編碼（字串或數值皆可；建議用純數字字串）。
Name ControlState 顯示名稱（給人看的）。
Format U4 SECS-II 格式（例如 U4 / I4 / ASCII / Boolean...）。
Type SVID 類型：常見 SVID / DVID。
Value 0 （可選）預設值；若你的整合是由程式更新，可先不填或填 0。
Units "" （可選）單位描述。

其他節點（ECs / Reports / CEIDs / Alarms）

這些節點用於完整 GEM 整合：事件回報、報表綁定、異常/警報 等。 若你目前只需要先把通訊跑通，可以先不建立；等整合到對應功能時再逐步補齊。

2.1 元件生命週期

本節說明如何在應用程式中正確地實例化、啟動與關閉 FluxSECS 通訊元件。

實例化與初始化

								FluxSECS.SECS secs = new FluxSECS.SECS();

// 初始化設定並訂閱 Log
secs.InitializeConfig(
    ConnectionPath: "Config/Connection.xml",
    GemDataPath: "Config/GemConfig.xml",
    StandardDataPath: "Config/Standard.xml",
    LicensePath: "Config/License.license",
    debugmode: true,
    monitor: (msg) => Console.WriteLine($"[MON] {msg}"),
    trace: (msg) => Console.WriteLine($"[TRC] {msg}")
);

啟動與關閉

  • Start(): 依據 Connection.xml 的設定 (HSMS) 啟動底層連線。
  • Close(): 正常關閉連線。若為 HSMS 連線中，會嘗試發送 Separate.Req 後再斷線。
  • Dispose(): 釋放物件所有資源，通常在程式結束時呼叫。

2.2 連線狀態管理

狀態定義

狀態名稱 詳細介紹
Disconnected 未連線
初始狀態，或網路/ComPort 已斷開。此時無法進行任何通訊。
Connected 物理連線已建立
  • HSMS: TCP Socket 已連線，但尚未進行 Select 握手。此時僅能發送控制訊息 (Select.Req)，不能發送資料訊息。
  • HSMS: 在 Connected 階段仍需完成 Select 握手；正式資料訊息建議於 Selected 後開始收送。
NotSelected (HSMS 專用) 等待握手
TCP 已連線，正在進行 HSMS Select 握手程序 (T7 Timeout 計時中)。
若為 Active 模式，表示已發送 Select.Req 等待回覆；若為 Passive 模式，表示正在等待對方發送 Select.Req。
Selected 通訊就緒
HSMS Select 握手已成功完成 (T3~T8 Timer 運作正常)。
這是唯一可以正常收發 SxFy 資料訊息的狀態。

事件監聽

應用程式應訂閱 ConnectStateChanged 事件以掌握連線狀況。

								secs.ConnectStateChanged += (state) => 
{
    Console.WriteLine($"連線狀態變更: {state}");
    if (state == ConnectState.Selected)
    {
        // HSMS Selected 後，可開始主動發送資料
        Console.WriteLine("通訊已建立，可以傳送訊息。");
    }
};

2.3 SECS Message建構

FluxSECS 採用物件導向方式建構 SECS-II 訊息。所有訊息皆由 SecsMessage 容器與內部的 SecsItem 資料單元組成。

SecsItem (資料單元)

SecsItem 是 SECS-II Body 的最小資料單元：每一顆 Item 都有一個 格式 (SecsFormat)，內容要嘛是 Scalar 值，要嘛是 List(巢狀子節點)。

  • List：用 Items 儲存子節點（可巢狀）。
  • Scalar：用 Values 儲存值；FluxSECS 內部以「字串」保存，編碼時才轉成對應型別。
  • B(Binary)：輸入可用十進位或十六進位；內部以十進位字串保存，但 SML/Log 會以 2 位十六進位顯示（例如 0x0A → 顯示 0A）。

支援的格式

SecsFormat SML 顯示 意義 範例
List L[n] 巢狀容器（子節點數量 n） new SecsItem() 或 new SecsItem(SecsFormat.List)
B B[n] Binary (byte) new SecsItem(SecsFormat.B, new[] { "0x00", "0xFF" })
Boolean BOOLEAN[n] 布林（0/1 或 true/false） new SecsItem(SecsFormat.Boolean, "true")
ASCII A[n] ASCII 字串（n=byte 長度） new SecsItem(SecsFormat.ASCII, "MDLN-01")
JIS8 J[n] JIS8 字串 new SecsItem(SecsFormat.JIS8, "日本語")
I1/I2/I4/I8 I1[n]... 有號整數（1/2/4/8 bytes） new SecsItem(SecsFormat.I4, "123")
U1/U2/U4/U8 U1[n]... 無號整數（1/2/4/8 bytes） new SecsItem(SecsFormat.U4, "1024")
F4/F8 F4[n]... 浮點數（4/8 bytes；允許科學記號） new SecsItem(SecsFormat.F8, "1.23E-4")

建立方式

方式 A：直接建立 Item（Scalar）
								// 單值
var u4 = new SecsItem(SecsFormat.U4, "100");

// 多值（例如 U4[3] 1 2 3）
var u4Multi = new SecsItem(SecsFormat.U4, new[] { "1", "2", "3" });

// ASCII（字串）
var mdln = new SecsItem(SecsFormat.ASCII, "MDLN-01");
方式 B：用 List 當容器，直接呼叫 Add_*（最簡潔）

當 SecsItem 本身是 List 時，呼叫 Add_U4/Add_ASCII/Add_B ... 會自動建立一顆子 Item並加入 List（你不需要自己 new 子節點）。

								// 建立 L,2 (MDLN, SOFTREV)
var root = new SecsItem(); // 預設就是 List
root.Add_ASCII("MDLN-01");
root.Add_ASCII("1.0.0");
方式 C：Object Initializer + L 初始化器（巢狀結構最清楚）
								var root = new SecsItem
{
    L =
    {
        new SecsItem(SecsFormat.ASCII, "MDLN-01"),
        new SecsItem(SecsFormat.ASCII, "1.0.0"),
        new SecsItem
        {
            L =
            {
                new SecsItem(SecsFormat.U4, "100"),
                new SecsItem(SecsFormat.Boolean, "true")
            }
        }
    }
};

收到訊息後取值

  • List 取子節點：可用索引器 root[0]，或用路徑 root.Get(new[] { 2, 1, 0 })。
  • Scalar 取值：用 Value（單值/合併字串）或 Values（字串陣列）。
								// 假設 Body 第一顆是 List
var root = msg.Items[0];

// L,2 (MDLN, SOFTREV)
string mdln = root[0].Value;
string softrev = root[1].Value;

// 也可以用 Get(路徑)
string first = root.Get(new[] { 0 }).Value;

B(Binary) 的輸入規則小心踩雷

FluxSECS 的 B 型態允許你用「十進位」或「十六進位」字串輸入：

  • 十六進位判斷：以 0x 開頭，或字串包含 A~F/a~f。
  • 內部保存：一律轉成十進位字串保存（例如 0xFF 會保存成 "255"）。
  • 顯示/輸出：ToString / SML / Log 會顯示成兩位十六進位（例如顯示 FF）。
								// 這三種都可以（結果都是同一個 byte 0x0A）
var b1 = new SecsItem(SecsFormat.B, "10");     // 十進位
var b2 = new SecsItem(SecsFormat.B, "0x0A");   // 十六進位（0x）
var b3 = new SecsItem(SecsFormat.B, "0A");     // 十六進位（含 A~F）

Remark（SML 註解覆蓋）

若你有使用 Standard.xml 產生 SML 註解，SecsItem.Remark 可用來「覆蓋」該節點的註解（優先於 Standard.xml）。你也可以使用帶 remark 的 Add_* 多載一次加入值與註解。

								var root = new SecsItem();
root.Add_U4("1001", "DATAID");          // 加值 + 註解
root.Add_ASCII("LOT-001", "LOTID");     // 加字串 + 註解

SecsMessage (訊息容器)

SecsMessage 代表一筆完整的 SECS 交易，包含 Header 與 Body (Stream, Function, W-Bit)。

								// 範例：建立 S1F1 (Are You There), W-Bit = True
var msg = new SecsMessage(1, 1, true);
// S1F1 通常沒有 Body，所以不需要 Add Item

2.4 基礎訊息收發

主動發送 (SendPrimary)

用於發起新的交易 (Primary Message)。若 Reply=true，元件會自動啟動 T3 Timer 等待回覆。

								// 範例：發送 S1F13 (建立通訊請求)
var s1f13 = new SecsMessage(1, 13, true);
// 組裝 Body: L,2 (MDLN, SOFTREV)
var root = new SecsItem(SecsFormat.List);
root.Add_ASCII("MDLN-01"); // Model Name
root.Add_ASCII("1.0.0");   // Software Rev
s1f13.Add(root);

// 發送
secs.SendPrimary(s1f13);

回覆 (OnDataMessage) 範例

在 WinForm 應用程式中，SECS 事件是在背景執行緒觸發的。為了安全更新 UI，建議使用 Invoke 或 BeginInvoke 回到 UI 執行緒，並使用 Switch-Case 進行訊息分流。

								// 在 Form_Load 或初始化時訂閱事件
secs.OnDataMessage += Secs_OnDataMessage;

private void Secs_OnDataMessage(TransactionType type, SecsMessage msg)
{
    // 切換到 UI 執行緒 (若需要更新 UI)
    this.Invoke((MethodInvoker)delegate
    {
        // 僅處理收到的 Primary 訊息
        if (type == TransactionType.PrimaryIn)
        {
            switch (msg.Stream)
            {
                case 1: // Stream 1
                    switch (msg.Function)
                    {
                        case 1: // S1F1 Are You There
                            // 回覆 S1F2
                            secs.Standard_S1F2(msg, "MY_MODEL", "1.0");
                            break;
                        case 13: // S1F13 Establish Comm
                            // 回覆 S1F14
                            secs.Standard_S1F14(msg, 0, "MY_MODEL", "1.0");
                            break;
                    }
                    break;

                case 2: // Stream 2
                    switch (msg.Function)
                    {
                        case 41: // S2F41 Host Command
                            // 自訂處理邏輯
                            HandleHostCommand(msg);
                            break;
                    }
                    break;
            }
        }
    });
}

FluxSECS 在記憶體中維護 GEM 資料模型，應用程式可透過下列 API 更新或讀取既有 VID / EC 的目前值。若要新增 VID / EC / Alarm / Report / CE 這類 GEM 模型定義，請參考 4.3。

4.2 GEM 控制狀態管理

控制狀態 (Control State) 是 GEM 標準中定義設備操作權限的核心狀態機。

狀態定義 (eControlState)

列舉值 說明
EqpOffLine 設備離線。
AttemptOnLine 嘗試連線。
HostOffLine Host 離線狀態。
OnLineLocal 連線中，但僅允許本地操作。
OnLineRemote 連線中，允許 Host 進行遠端控制。

狀態判定矩陣

FluxSECS 內部透過以下幾個布林旗標的組合，即時計算出當前的 ControlState：

標準 SEMI 的情況 FluxSECS 會自己計算，若非標準請用以下提供的 API 轉換。

狀態轉換機制

自動轉換 (收到訊息時)

  • S1F13 (Establish Comm): 連線建立完成。
  • S1F15 (Req Offline): HostOnLine = false。
  • S1F17 (Req Online):
    • 設定 HostOnLine = true。
    • 關鍵邏輯：此時設備將根據 GemConfig.xml 中的 <DefaultOnlineState> 設定，自動決定進入 OnLineLocal 或 OnLineRemote。
      (0 = Local, 1 = Remote)。

手動轉換 (API)

SetEQPOnLine(bool) 設備主動切換離線/上線。

4.3 用程式碼新增/修改/移除 GEM 定義

本節說明如何用程式碼新增、修改或移除 GEM 模型定義，例如 VID、EC、Alarm、Report、CE。這裡處理的是「ID 與模型定義」，不是 VID / EC 的目前值。

範例皆使用 FluxSECS.dll / SF.dll 原本公開的 API。

儲存方式：用程式碼新增或修改的 VID / EC / Alarm / Report / CE 會先存在記憶體；需要重啟後保留時，再呼叫 SaveGemConfig() 儲存回 GemConfig.xml。

GEM 模型定義 API 對照

項目 新增定義 確認定義存在 讀取定義物件 移除定義
VID secs.GEM.AddVID(new VID(id)) secs.GEM.VIDs.isExist(id) secs.GEM.VIDs[id] secs.GEM.RemoveVID(id)
EC secs.GEM.AddEC(new EC(id)) secs.GEM.ECs.isExist(id) secs.GEM.ECs[id] secs.GEM.RemoveEC(id)
Alarm secs.GEM.AddAlarm(new Alarm(id, alcd, altx)) secs.GEM.Alarms.isExist(id) secs.GEM.Alarms[id] secs.GEM.RemoveAlarm(id)
Report secs.GEM.AddReport(new Report(id)) secs.GEM.Reports.isExist(id) secs.GEM.Reports[id] secs.GEM.RemoveReport(id)
CE secs.GEM.AddCE(new CE(id)) secs.GEM.CEs.isExist(id) secs.GEM.CEs[id] secs.GEM.RemoveCE(id)

新增 VID 定義

VID Type 建議只使用 SVID 或 DVID。新增 VID 只是增加 GEM 模型項目，不代表已更新 VID 目前值。

using FluxSECS;

var vid = new VID("1001")
{
    Name = "ControlState",
    SecsFormat = SecsFormat.ASCII,
    Type = "SVID",
    Units = ""
};

secs.GEM.AddVID(vid);

修改既有 VID 定義

if (secs.GEM.VIDs.isExist("1001"))
{
    VID vid = secs.GEM.VIDs["1001"];
    vid.Name = "ControlState";
    vid.SecsFormat = SecsFormat.ASCII;
    vid.Type = "SVID";
    vid.Units = "";
}

新增 EC 定義

新增 EC 是增加新的 ECID 與模型定義。若要更新 EC 目前值，另外使用 4.1 的 SetEcValue 或 TrySetEcValue。

var ec = new EC("2001")
{
    Name = "TimeoutSec",
    SecsFormat = SecsFormat.U4,
    Min = "1",
    Max = "3600",
    Default = "30",
    Units = "sec"
};

secs.GEM.AddEC(ec);

修改既有 EC 定義

if (secs.GEM.ECs.isExist("2001"))
{
    EC ec = secs.GEM.ECs["2001"];
    ec.Name = "TimeoutSec";
    ec.SecsFormat = SecsFormat.U4;
    ec.Min = "1";
    ec.Max = "3600";
    ec.Default = "30";
    ec.Units = "sec";
}

新增 Alarm 定義

Alarm.ALCD 與 Alarm.ALTX 是唯讀屬性；新增時可用建構子指定，既有 Alarm 要修改時使用 SetALCD / SetALTX。ALCD 建議填未發生時的 base code，例如 "0"；發生/解除時由 SendAlarmSet / SendAlarmClear 處理 bit 7。

var alarm = new Alarm("3001", "0", "Door Open")
{
    Enable = true
};

secs.GEM.AddAlarm(alarm);

修改既有 Alarm 定義

if (secs.GEM.Alarms.isExist("3001"))
{
    secs.SetALCD("3001", "0");
    secs.SetALTX("3001", "Door Open");
    secs.GEM.AlarmEnable("3001", true);
}

新增 Report 定義

Report 本身沒有資料值；Report 只定義 RPTID 與 VID 清單。

var report = new Report("5001")
{
    Name = "BasicReport",
    DataID = "0"
};

report.ReplaceReportVids(new[] { "1001", "1002", "1003" });
secs.GEM.AddReport(report);

修改既有 Report 定義

if (secs.GEM.Reports.isExist("5001"))
{
    Report report = secs.GEM.Reports["5001"];
    report.Name = "BasicReport";
    report.DataID = "0";
    report.ReplaceReportVids(new[] { "1001", "1002", "1003" });
}

新增 CE 定義

CE 本身沒有 Value，它只記錄 CEID、名稱、Enable 狀態，以及綁定哪些 Report。S6F11 的資料值是透過 CE → Report → VID 取得 VID 目前值。

var ce = new CE("9001")
{
    Name = "ProcessStarted",
    Enable = true
};

ce.ReplaceReports(new[] { "5001" });
secs.GEM.AddCE(ce);

修改既有 CE 定義

if (secs.GEM.CEs.isExist("9001"))
{
    CE ce = secs.GEM.CEs["9001"];
    ce.Name = "ProcessStarted";
    ce.Enable = true;
    ce.ReplaceReports(new[] { "5001" });
}

完整範例：用程式碼建立新的 GEM ID 並送 Event / Alarm

using FluxSECS;

// 1. 新增 VID ID
secs.GEM.AddVID(new VID("1001")
{
    Name = "ControlState",
    SecsFormat = SecsFormat.ASCII,
    Type = "SVID"
});

secs.GEM.AddVID(new VID("1002")
{
    Name = "LotID",
    SecsFormat = SecsFormat.ASCII,
    Type = "SVID"
});

secs.GEM.AddVID(new VID("1003")
{
    Name = "CarrierID",
    SecsFormat = SecsFormat.ASCII,
    Type = "DVID"
});

// 2. 新增 ECID
secs.GEM.AddEC(new EC("2001")
{
    Name = "TimeoutSec",
    SecsFormat = SecsFormat.U4,
    Min = "1",
    Max = "3600",
    Default = "30",
    Units = "sec"
});

// 3. 新增 ALID
secs.GEM.AddAlarm(new Alarm("3001", "0", "Door Open")
{
    Enable = true
});

// 4. 新增 RPTID，Report 內放 VID ID
var report = new Report("5001")
{
    Name = "BasicReport",
    DataID = "0"
};
report.ReplaceReportVids(new[] { "1001", "1002", "1003" });
secs.GEM.AddReport(report);

// 5. 新增 CEID，並把 CEID 綁定 Report
var ce = new CE("9001")
{
    Name = "ProcessStarted",
    Enable = true
};
ce.ReplaceReports(new[] { "5001" });
secs.GEM.AddCE(ce);

// 6. 若要重啟後保留新增的 ID，請儲存回 GemConfig.xml
secs.SaveGemConfig();
// 或指定路徑：secs.GEM.SaveGemConfig(@"C:\FluxSECS\GemConfig.xml");

// 7. 下面是更新值，不是新增 GEM ID。
// S6F11 發送前可先更新 Report 內 VID 的目前值。
// CE 本身沒有值；S6F11 會依 CE -> Report -> VID 取得 VID 值。
secs.SetVidValue("1001", "RUNNING");
secs.SetVidValue("1002", "LOT002");
secs.SetVidValue("1003", "CST002");

secs.SendEvent("9001", SecsFormat.U4, SecsFormat.U4, SecsFormat.U4);

// 8. 發送 S5F1 Alarm Set / Clear
secs.SendAlarmSet("3001", 0, SecsFormat.U4);
secs.SendAlarmClear("3001", 0, SecsFormat.U4);

移除 GEM 定義

// 移除 CE / Report / VID / EC / Alarm 定義
secs.GEM.RemoveCE("9001");
secs.GEM.RemoveReport("5001");
secs.GEM.RemoveVID("1003");
secs.GEM.RemoveEC("2001");
secs.GEM.RemoveAlarm("3001");

// 需要保留到 XML 時才呼叫
secs.SaveGemConfig();
使用區分：新增或修改 GEM 模型定義時使用 GEM.Add* / GEM.Remove* 與對應集合；更新 VID / EC 目前值時使用 4.1 的 SetVidValue、TrySetVidValue、SetEcValue、TrySetEcValue。CE 只負責事件定義與 Report 綁定，沒有 CE 值。
